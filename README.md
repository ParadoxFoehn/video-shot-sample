# video-shot-sample

> **给视频抽帧，用最少的帧说清「这条片子发生了什么」。**
> 面向多模态模型 / AI 助手 / 视频笔记：一条 2 分钟的视频，8 张图、约 2000 token，
> 就能覆盖全片的关键状态，包括**只出现 1 秒的广告插播**。

```
127 秒的 MV  →  31 帧  →  8 张 4 拼 1 图  →  约 2042 token
```

## 它解决什么问题

让 AI「看懂视频」，常见做法有两种，各有硬伤：

| 做法 | 拿到什么 | 丢掉什么 |
| --- | --- | --- |
| 截图 + OCR | 屏幕上的文字 | 动作、过程、语气、音乐；错了没人发现 |
| 均匀抽帧拼图 | 全片大致结构 | 每格小到读不出字；密集段被平均掉 |

这个工具换了个判据：**不是「哪一段重要」，而是「这一帧能不能被两侧的帧推出来」**。

- 镜头之内动画连续（走路、平移、光线渐变）→ 中间过程能推断 → **一帧都不给**
- 镜头切换、画风突变（插播、闪回、字幕卡）→ 这是无法推断的信息 → **给一帧**
- 长镜头太久没采样 → **补一个点**，避免中间藏事件

一句话：**你能推出来的地方，我不花钱；推不出来的地方，一定给你一帧。**

## 效果（实测数据）

测试素材：127.15 秒动画 MV，65 个切点，音乐驱动，其中 **30.6 秒有一个 1 秒的软过渡广告插播**。

| 方案 | 帧数 | 图片张数 | ≈token | 结果 |
| --- | --- | --- | --- | --- |
| 均匀 16 格 | 22 | 1 | 557 | 便宜，但 90–100 秒整段没被覆盖 |
| **本工具 · 24 帧** | 24 | 6 | 1594 | 故事线完整，但会漏掉 1 秒插播 |
| **本工具 · 32 帧（推荐）** | 31 | 8 | **2042** | 状态全覆盖，插播有自己的一格 |
| 本工具 · 48 帧 | 48 | 12 | 2938 | 更全，但约 1/3 是同场景重复 |
| 全片 0.3 秒密采 | ~420 | 105 | 24000+ | 大量重复帧，没人会看完 |

**关键证据（为什么需要第二路判据）**：那段 1 秒插播进场时

```
像素差     54.89   ← 低于 27.5 秒一次镜头晃动的 68.23
颜色直方图 0.595   ← 同一位置，全段最高
```

只按像素差选帧，**这个插播永远选不到**；加上颜色直方图，一次就中。

## 安装

**依赖**：Python 3.8+、ffmpeg（含 ffprobe）、numpy；出图另需 Pillow。

```bash
# 克隆
git clone https://github.com/ParadoxFoehn/video-shot-sample.git
cd video-shot-sample

# 依赖
pip install numpy pillow

# 检查环境（会逐项报缺什么）
python scripts/shot_sample.py --doctor
```

`--doctor` 正常输出：

```
ffmpeg   /usr/bin/ffmpeg
ffprobe  /usr/bin/ffprobe
python   3.12.1
numpy    OK
PIL      OK

结论：环境可用
```

缺 ffmpeg 的装法：

| 系统 | 命令 |
| --- | --- |
| Windows | `winget install ffmpeg` 或 `scoop install ffmpeg` |
| macOS | `brew install ffmpeg` |
| Ubuntu/Debian | `sudo apt install ffmpeg` |

> **Windows 注意**：`python` 若指向 Microsoft Store 的占位程序（运行后弹商店），
> 请用真实 Python 的完整路径调用，或改用 `py -3 scripts/shot_sample.py ...`。

## 快速开始

```bash
# 1) 只出计划（最快，几秒钟）
python scripts/shot_sample.py video.mp4 --out out/

# 2) 出计划 + 4 拼 1 图
python scripts/shot_sample.py video.mp4 --out out/ --render

# 3) 想要更细
python scripts/shot_sample.py video.mp4 --out out/ --max 48 --render

# 4) 自测（不需要任何素材，自动生成 12 秒合成片跑一遍）
python scripts/shot_sample.py --selftest
```

正常输出：

```
时长 127.1s ｜ 1920x1080 ｜ 24 fps
切点 56 个
保留 31 帧 → 8 张 4拼1 ｜ 预计 ≈2042 token
采样点：2.4, 7.6, 12.3, 17.9, 23.1, 25.6, 30.6, ...
完成，产物在 /path/to/out
```

## 输出文件说明

### `plan.json`（给程序读）

```json
{
  "video": "v1.mp4",
  "duration": 127.09,
  "cuts": 56,
  "changes": 46,
  "samples": [2.4, 7.6, 12.3, "..."],
  "sheets": 8,
  "token_est": 2042
}
```

### `manifest.md`（给人读）

```
# 抽帧清单 | v1.mp4 | 127.1s | 31 帧 / 8 张 4拼1 / ≈2042 token
# 切点 56 ｜ 状态变化点 46 ｜ 直方图阈值 0.380
# 帧号|时间|所属区间|像素差|直方图差|来源
1|2.40s|2.0-2.8s|45.12|0.410|状态变化
2|7.60s|7.1-8.0s|31.08|0.220|镜头
```

- **像素差**：与上一分析帧的平均亮度差（0–255）
- **直方图差**：与上一分析帧的颜色分布总变差（0–1，越大画风变得越多）
- **来源**：`状态变化`（直方图峰）或 `镜头`（镜头级兜底）

### `sheets/sheet_01.png …`（`--render` 才有）

每张 4 帧，2×2 排列，帧下标着时间戳。按编号顺序读就是时间顺序。

## 参数怎么调

| 参数 | 默认 | 作用 | 调大 | 调小 |
| --- | --- | --- | --- | --- |
| `--max` | 36 | 总帧数上限 | 覆盖更全、更贵 | 更省、可能漏状态 |
| `--max-gap` | 8 | 相邻采样点最大间隔（秒） | 长镜头中间不补，可能漏事件 | 补得密，token 涨 |
| `--hist-threshold` | 0.22 | 颜色直方图突变阈值（0–1） | 只抓剧烈画风变化，软过渡易漏 | 抓得多，可能把镜头晃动当状态 |
| `--cut-threshold` | 0.30 | scene 切点阈值（0–1） | 只认很明显的硬切 | 切点更多，噪声也多 |
| `--no-cuts` | 关 | 完全不做切点检测 | — | — |
| `--render` | 关 | 出 4 拼 1 图 | — | — |

**换算**：1 张 4 拼 1 ≈ **224 token**；`token ≈ 张数 × 224 + 清单 250`。

**一条经验**：先跑默认值，看 `manifest.md` 里的「直方图差」和「像素差」分布，
再决定调哪个。**不要凭感觉直接改阈值。**

典型调法：

| 想要 | 做法 |
| --- | --- |
| 只想快速扫一眼 | `--max 12 --no-cuts`（只看画风变化） |
| 精读一条片子 | `--max 32 --render` |
| 广告 / 鬼畜 / 快剪 | `--max 48 --hist-threshold 0.18` |
| 静态演示 / 录屏 | `--max 16 --max-gap 20` |
| 漏了某个关键画面 | 先把 `--hist-threshold` 降到 0.15 试；还不行就 `--cut-threshold 0.2` |

## 它是怎么工作的

### 两路判据

| 判据 | 抓什么 | 漏什么 |
| --- | --- | --- |
| 切点（ffmpeg `scene`） | 硬切 | 不到 1 秒的软过渡 |
| 像素差（灰度平均绝对差） | 晃动、闪光 | 画风渐变 |
| **颜色直方图（8×8×8 RGB）** | **画风/内容突变** | 颜色相近但内容不同的切换 |

### 选帧五步

```
① 状态点先占位   直方图峰值处取「变化后 0.35 秒」，最多占一半预算，彼此 ≥2.5 秒
② 保首尾         整片开头与结尾各留一帧
③ 覆盖优先       从最大空档开始补点，补在区间内「像素差峰值」处；太偏就退回中点
④ 价值填满       剩余预算给「变化大且离已选帧远」的候选
⑤ 近邻合并       间距 <0.6 秒视为同一状态，只留一个
```

### 实现要点（想改代码时看这里）

| 位置 | 干什么 | 改它会怎样 |
| --- | --- | --- |
| `decode_features()` | 一次解码全片为 4fps / 64×36 的 RGB，同时算亮度与直方图 | 改 `ANALYZE_FPS` 影响精度与速度；改 `FEAT_W/FEAT_H` 影响灵敏度 |
| `detect_cuts()` | 用 `select='gt(scene,T)'` 拿时间戳 | 切点漏检就调小 `--cut-threshold` |
| `build_plan()` | 上面五步全在这里 | 想换选帧策略只改这个函数 |
| `render_sheets()` | 抽帧拼图（Pillow） | 改 `thumb_w` 控制单帧宽度 |
| `TOK_PER_SHEET` | 常量，按一屏 224 token 估 | 换模型后按实测改 |

详细算法与推导见 [`docs/ALGORITHM.md`](docs/ALGORITHM.md)，实测数据集见 [`docs/MEASURED.md`](docs/MEASURED.md)。

## 出问题时怎么改

> 下面的「先看什么」是排查顺序，不是猜测。

| 现象 | 先看什么 | 原因 | 处置 |
| --- | --- | --- | --- |
| 一帧都没选出来 | 输出里「切点 N 个」是否为 0 | 视频无切点、直方图也没超过阈值 | 调小 `--hist-threshold 0.15`，或去掉 `--no-cuts` |
| 只剩 1–2 帧 | `--max` 是否太小 | 预算小于必要覆盖 | `--max 24` 起 |
| 漏掉某段关键画面 | `manifest.md` 里该时段有没有采样点 | 该段变化不够大，被判为「可推断」 | 降 `--hist-threshold`；仍不行就对那一段单独密采（见下） |
| 采到的全是同一场景 | 「直方图差」是否都很小 | 阈值太高 | `--hist-threshold 0.18` |
| 帧数远超预期 | `--max` 与 `--max-gap` | `--max-gap` 太小会把长片撑满 | `--max-gap 12` |
| 出图很慢 | 是否用了 `--render` | 每帧要单独 seek 解码一次 | 只在需要时加；或先出 `plan.json` |
| 报 `找不到 ffmpeg` | `--doctor` | ffmpeg 不在 PATH | 装 ffmpeg，或用绝对路径加入 PATH |
| 报 `需要 numpy` | `--doctor` | 没装依赖 | `pip install numpy` |
| 提示「没装 Pillow，跳过出图」 | `--doctor` | `--render` 需要 Pillow | `pip install pillow`，或不要 `--render` |
| 中文全变方块 | 系统缺中文字体 | 图上的时间戳用系统字体 | 装任一中文字体；或改 `render_sheets()` 里的字体路径 |
| Windows 下 python 弹商店 | `where python` | 指向 Store 占位程序 | 用真实 Python 完整路径，或 `py -3` |
| 时长读成 0 | `ffprobe` 是否可执行 | 容器封装异常 | 先 `ffmpeg -i video.mp4` 看是否正常解码 |

**需要看某一段的细节时**（本工具只给「状态帧」，不给过程帧）：

```bash
# 用 ffmpeg 对指定区间按 0.3 秒一帧密采
ffmpeg -ss 100 -to 106 -i video.mp4 -vf fps=3.3 -q:v 3 seg_%03d.jpg
```

## 能力边界

- **只给状态帧，不给过程帧**：一段连续旋转的舞蹈，工具只给 1–2 帧；要看过程请对那段密采。
- **快剪（每 0.2 秒一刀）会吃满预算**：混剪类素材建议 `--max 48`，或按段落分段跑。
- **溶接 / 淡变不产生切点**：这类转场靠直方图与补点兜住，但极端缓慢的渐变仍可能漏。
- **字幕带变化会被当成状态变化**：这是刻意的（电影里字幕能单独承担信息），
  在字幕逐句滚动的片子里会多给几帧。想省就把 `--hist-threshold` 调高。
- **不发声音**：本工具只看画面。声音请另接转写 / 节拍分析。
- **token 估算是经验值**：按「一屏 4 拼 1 ≈ 224 token」估，换模型请按实测改 `TOK_PER_SHEET`。

## 开发与测试

```bash
# 环境自检
python scripts/shot_sample.py --doctor

# 端到端自测（自动生成合成片，不需要素材）
python scripts/shot_sample.py --selftest

# 回归：拿一条已知片子跑，采样点应稳定
python scripts/shot_sample.py sample.mp4 --out /tmp/t1 --max 32
python scripts/shot_sample.py sample.mp4 --out /tmp/t2 --max 32
diff /tmp/t1/plan.json /tmp/t2/plan.json    # 应完全一致（算法是确定性的）
```

改代码的原则：

1. **保持确定性**：同样的输入必须给同样的采样点（没有随机数）。
2. **先打印中间量**：改阈值类参数时，把「切点数 / 变化点数 / 实际阈值」打印出来，
   否则规则「跑通了」不等于「生效了」。
3. **用真实片子回归**：合成片能过不代表真实素材能过。
