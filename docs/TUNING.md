# 阈值怎么调

> 调参的顺序永远是：**先跑默认 → 看 `manifest.md` 里的两列数值 → 再决定动哪个**。
> 不要凭感觉直接改阈值。

---

## 先看这两个数

打开 `manifest.md`：

```
# 帧号|时间|所属区间|像素差|直方图差|来源
1|2.40s|2.0-2.8s|45.12|0.410|状态变化
2|7.60s|7.1-8.0s|31.08|0.220|镜头
```

| 列 | 范围 | 含义 |
| --- | --- | --- |
| 像素差 | 0–255 | 与上一分析帧的亮度差。>40 通常是一次明显变化 |
| 直方图差 | 0–1 | 与上一分析帧的颜色分布差异。>0.25 通常是画风变了 |

**判读**：

- 两列都普遍很低（像素差 <10、直方图差 <0.05）→ 片子很静，减少 `--max`
- 像素差很高但直方图差低 → 多是镜头晃动/闪光，属于「动但没变内容」
- 直方图差高而像素差中低 → 画风变了（插播、换场景），**正是要抓的**

## 四种典型素材的起步参数

| 素材类型 | 起步参数 | 理由 |
| --- | --- | --- |
| 口播 / 讲解 / 录屏 | `--max 16 --max-gap 20` | 画面基本不变，靠台词；帧多了浪费 |
| 动画 MV / 短剧 | `--max 32 --render` | 切点多、画风变化大，默认值就够 |
| 广告 / 鬼畜 / 混剪 | `--max 48 --hist-threshold 0.18` | 快切且插播多，需要更灵敏 |
| 长电影 / 纪录片 | `--max 48 --max-gap 12` | 长镜头多，靠空档上限控制覆盖 |

## 症状 → 调什么

| 症状 | 先调 | 再调 |
| --- | --- | --- |
| 漏了某段关键画面 | `--hist-threshold` 降到 0.15 | `--cut-threshold` 降到 0.2 |
| 采到的全是同一场景 | `--hist-threshold` 降到 0.18 | `--max` 提高 |
| 帧太多太贵 | `--max` 降到 20 | `--hist-threshold` 提到 0.3 |
| 中间有大段空白 | `--max-gap` 降到 5 | `--max` 提高 |
| 每帧之间太近（重复） | `--hist-threshold` 提到 0.28 | `--max` 降低 |
| 切点太少（快剪没抓到） | `--cut-threshold` 降到 0.2 | 用 `--no-cuts` 只靠直方图 |

## 三个常有误解的点

**① `--max` 不是「一定给这么多帧」**
它是上限。片子很静时实际帧数会少于 `--max`。

**② `--hist-threshold` 会与自动阈值取大者**
代码里 `thr_h = max(hist_threshold, 直方图差的 P90)`。
所以你把阈值调得很低，实际生效值仍可能是 P90——**启动输出里会打印实际阈值**，
看那一行就知道到底用了多少。

**③ token 只与「张数」有关，与帧数无关**
一屏塞 4 帧还是 8 帧，画布大小差不多（约 220–230 token）；
**多出一张图才 +224**。所以「省 token」要省图，别省帧数到看不清。

## 想验证改对了没有

```bash
# 同一份输入跑两次，采样点必须完全一致（算法是确定性的）
python scripts/shot_sample.py v.mp4 --out /tmp/a --max 32 --quiet
python scripts/shot_sample.py v.mp4 --out /tmp/b --max 32 --quiet
diff /tmp/a/plan.json /tmp/b/plan.json
```

改完之后，至少用**两类不同素材**回归：一条口播、一条快剪。
只测一种，很容易把另一类调坏。
